Corrected the ``readingtime`` estimates, which were counting the markup of a
page rather than the page. The words are now counted on the parsed document,
so directive names, option lines, link targets and comments no longer inflate
the figure, and a body produced by another directive is included in it.
Counting the source ran between 1.3 and 2.0 times the rendered word count, so
every calculated estimate moves: :ref:`tippy-gv-developer-testing` drops from
``37`` minutes to ``22``, and :ref:`tippy-gv-installation` from ``6`` to ``3``.

The default rate is now ``150`` words-per-minute rather than ``120``, pitched
below the ``175`` to ``300`` band that `Brysbaert (2019)
<https://doi.org/10.1016/j.jml.2019.104047>`__ reports for adults reading
English non-fiction, because these pages alternate prose with code and output
that a reader works through line by line. The paper is cited on
:ref:`tippy-gv-developer-documentation`, and the bibliography on
:ref:`tippy-gv-reference-about-community-publications` is filtered so that a
work the documentation cites for its own reasons is not listed there as a
publication using ``geovista``.

The banner is built from docutils nodes rather than a raw ``HTML`` block, so a
``text``, ``man`` or ``latex`` build carries the estimate too, and its
stylesheet now asks the theme for colours the theme defines. It had been asking
for ``--article-info-bg`` and ``--article-info-fg``, which neither theme
defines, and a custom property that resolves to nothing fails silently, so the
banner published a transparent box. An argument the directive does not
understand fails the build rather than being ignored. (:user:`claude`)
