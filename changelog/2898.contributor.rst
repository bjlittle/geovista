The :ref:`How We Work <gv-developer-workflow>` page gains three rules that were
written down elsewhere: confirm a roadmap row is bounded before planning it,
record deferred work as an open item of its specification, and settle the
specification items of an issue in the pull request that closes it. A fourth
says when a change to a rule retires it. Under it, the rule on changelog
fragments is retired for one that also lets a pull request which only records
open work in a specification skip its fragment. (:user:`claude`)
